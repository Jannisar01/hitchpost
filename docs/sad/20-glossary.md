## 1. Purpose and scope

One meaning per term across the whole package. Where a term has a general industry meaning and a narrower Hitchpost meaning, the Hitchpost meaning is given and the difference noted. Other documents link here instead of redefining terms.

## 2. Terms

| Term                                 | Definition                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A2A (Agent2Agent)                    | Open protocol, now a Linux Foundation project, for agents to discover each other and exchange messages and tasks. Hitchpost uses specification v1.0 through `@a2a-js/sdk` 1.3 ([ADR 0003](../decisions/0003-build-on-a2a-and-mcp.md)).                                                                                                                                                                       |
| ADR (architecture decision record)   | Short numbered record of one significant decision: context, decision, alternatives, consequences. Kept in `docs/decisions/`.                                                                                                                                                                                                                                                                                 |
| Agent                                | Software that acts for one party. A _business agent_ acts for a business; a _personal agent_ acts for a person.                                                                                                                                                                                                                                                                                              |
| Agent line                           | The Hitchpost identity of one person or business: an A2A Agent Card plus a contact list of other agent lines. Hitchpost is a network of agent lines between users, person to person and person to business; barbers are the beachhead vertical, not the product. People's lines are free; a verified business agent line has a flat monthly subscription after the pilot (P-26).                             |
| Agent Card                           | JSON document an A2A agent publishes at `/.well-known/agent-card.json` describing its name, endpoint, skills and accepted contract versions.                                                                                                                                                                                                                                                                 |
| Agent record                         | The structured behaviour metrics shown for a business agent (response time, offers honored, reports), as distinct from human star ratings (FR-RATE-02).                                                                                                                                                                                                                                                      |
| Appointment book                     | The business's schedule: services, opening hours and booked time ranges. In-memory in Phase 1 (`book.ts`); a real booking system over MCP later.                                                                                                                                                                                                                                                             |
| Approval                             | A recorded human yes to one specific offer. In code, a value only the approval gate can create, bound to one `offerId` and expiring with it (FR-GATE-02, FR-GATE-04).                                                                                                                                                                                                                                        |
| Approval gate                        | The component and rule that nothing committing a person (time, money, personal data) happens without that person's approval ([ADR 0007](../decisions/0007-human-approval-gate.md)). The trust floor of the product, not its moat.                                                                                                                                                                            |
| Approval sheet                       | The client app screen that shows a validated offer and the Approve and Decline buttons.                                                                                                                                                                                                                                                                                                                      |
| Audit log                            | Append-only record of offers, decisions and booking results kept on both sides of an exchange (FR-GATE-03).                                                                                                                                                                                                                                                                                                  |
| Availability request                 | Message kind asking a business agent for the first free slot for a service within a time window.                                                                                                                                                                                                                                                                                                             |
| Baseline                             | An approved version of a document or document set that changes only through change control (HP-SAD-00).                                                                                                                                                                                                                                                                                                      |
| Booking                              | A confirmed time range in the business's appointment book for one person and one service.                                                                                                                                                                                                                                                                                                                    |
| Booking request                      | Message kind by which a personal agent, after approval, asks the business agent to book a specific stored offer. The server-minted `offerId` is the capability that authorises it; `contextId` grants nothing. A resend without the `taskId` is answered with the original `booking_confirmed` plus `duplicateOf` (FR-BOOK-07). After approval it carries the customer contact block.                        |
| Booking outcome                      | What happened to a booking once its time has passed: **Completed** (the customer came), **NoShow** (they didn't), **Disputed** (the business's mark and the customer's answer disagree; operator review) or **Unresolved** (no mark within P-25, 7 days; excluded from the north star). The business marks; the customer answers "Did it go as booked?" (FR-RATE-04, FR-RATE-05). Outcomes are never billed. |
| Booking token (`bookingToken`)       | Server-minted secret returned in `booking_confirmed` and stored only as a hash; it must be presented with `cancel_request` and `reschedule_request` (FR-MSG-12).                                                                                                                                                                                                                                             |
| BRD (business requirements document) | The document stating the business need, objectives, scope, as-is and to-be processes and business requirements (BR-REQ-), from which the PRD and the SRS follow (HP-SAD-23).                                                                                                                                                                                                                                 |
| Built                                | Status label meaning the item exists in the code today, with a path or test cited.                                                                                                                                                                                                                                                                                                                           |
| Business rule                        | A constraint the system enforces regardless of interface, numbered BR-nn in HP-SAD-07.                                                                                                                                                                                                                                                                                                                       |
| C4 model                             | Notation for architecture diagrams at context, container, component and code levels.                                                                                                                                                                                                                                                                                                                         |
| Cold start                           | The two-sided problem that a directory without businesses has no users, and without users attracts no businesses.                                                                                                                                                                                                                                                                                            |
| Conformance kit                      | JSON Schemas for every `hitchpost/1` message kind plus a runner a developer points at their agent's URL to prove it speaks the contract. Open, released with each contract version (Phase 2, WP-2.14).                                                                                                                                                                                                       |
| Contract version                     | The major version of the Hitchpost message contract an agent accepts, declared on its Agent Card as an `AgentCapabilities.extensions` entry (`https://hitchpost.dev/ext/contract/v1` from Phase 2); clients declare it in the `A2A-Extensions` header. Major versions only (P-18).                                                                                                                           |
| contextId                            | A2A identifier that ties the messages and tasks of one conversation together. The client may choose it and the SDK keeps the client's value, so it is used for **correlation only** and grants nothing; authority comes from the server-minted `offerId` and `bookingToken` (FR-MSG-12).                                                                                                                     |
| Correlation fields                   | `contextId`, `taskId`, `offerId` and `messageId`, recorded on every audit event from Phase 2 so one booking can be followed across both sides (FR-MSG-11).                                                                                                                                                                                                                                                   |
| Counter-metric                       | A metric that must not get worse while the north star grows (for example first-offer rejection rate, or the unmarked outcome rate).                                                                                                                                                                                                                                                                          |
| Customer contact block               | The person's display name, verified phone and an optional note, sent with `booking_request` only after the person approves and shared only with that business. Classed Sensitive and retained per P-12 (Phase 2).                                                                                                                                                                                            |
| Data part                            | A2A message part carrying structured JSON, as opposed to a text part. All Hitchpost booking messages travel as data parts ([ADR 0010](../decisions/0010-typed-data-parts-before-llm.md)).                                                                                                                                                                                                                    |
| Directory                            | Public, searchable register of verified business agent lines (Phase 3). People's agent lines are not listed publicly.                                                                                                                                                                                                                                                                                        |
| Disputed                             | Booking outcome when the business's mark and the customer's answer disagree; resolved by operator review and never billed.                                                                                                                                                                                                                                                                                   |
| FURPS+                               | Requirements classification: functionality, usability, reliability, performance, supportability, plus design, implementation, interface and physical constraints. Each requirement in the PRD carries one class (HP-SAD-24).                                                                                                                                                                                 |
| Expiry (`expiresAt`)                 | The instant an offer stops being bookable and its hold is released: `issuedAt` plus P-01 (10 minutes), on the business clock. The personal agent treats it as expired 30 seconds early (P-09).                                                                                                                                                                                                               |
| Honored booking                      | A booking whose outcome is Completed. The north star counts these.                                                                                                                                                                                                                                                                                                                                           |
| Hold                                 | Temporary reservation of a slot while an offer is open (P-01), so it can't be offered to someone else. Capped per sender (P-07), where the sender is the install key, falling back to the IP, until agent identity in Phase 6.                                                                                                                                                                               |
| Install key                          | A random key generated per personal-agent install and sent in a request header. It keys the open-holds cap and the rate limit from Phase 2 (P-07, P-08), so many people behind one carrier IP aren't locked out. Replaced by agent identity in Phase 6.                                                                                                                                                      |
| `issuedAt`                           | The business agent's clock time when it created an offer. The business clock is authoritative for expiry.                                                                                                                                                                                                                                                                                                    |
| Kill criterion                       | A pre-set result of an assumption test that stops or changes the plan. For A-01 it is the kill band of pre-registered continue / iterate / kill bands, read with 95% confidence intervals.                                                                                                                                                                                                                   |
| Levels of automation                 | A scale of how much a system decides and acts on its own versus a human, from "the human does everything" to "the system acts and doesn't tell the human". Hitchpost places each function on it and keeps every commitment at "the system proposes, the human approves" (HP-SAD-32).                                                                                                                         |
| Listing                              | A directory entry for one business agent, pointing to its Agent Card.                                                                                                                                                                                                                                                                                                                                        |
| Listing origin                       | The scheme, host and port a listing was verified for. A card's interface URL must match it (FR-DIR-03).                                                                                                                                                                                                                                                                                                      |
| Manual approval                      | **Later** (not in the pilot). A per-business setting under which the owner accepts each booking. As designed, the booking Task stays WORKING with a "waiting for the shop" status, the slot is reserved, and the personal agent polls `GetTask`; after P-03 (30 minutes) it ends with `shop_timeout` (FR-GATE-05). It doesn't use input-required, which in A2A means the client must reply.                  |
| MCP (Model Context Protocol)         | Open protocol connecting an agent to its own tools and data. Planned for reaching real booking systems; not used in Phase 1.                                                                                                                                                                                                                                                                                 |
| MoSCoW                               | Prioritisation into Must have, Should have, Could have and Won't have (this time). Applied to every requirement in the PRD (HP-SAD-24).                                                                                                                                                                                                                                                                      |
| Message (A2A)                        | A single A2A exchange unit. Hitchpost uses Messages for stateless questions (availability).                                                                                                                                                                                                                                                                                                                  |
| Normative parameter (P-nn)           | A value or phase used in more than one document, kept once in [00](00-document-control.md#10-normative-parameters-and-phase-map) and cited by its ID everywhere else.                                                                                                                                                                                                                                        |
| North star                           | The one metric the product is steered by: weekly human-approved bookings that were honored, meaning their outcome is Completed.                                                                                                                                                                                                                                                                              |
| Offer                                | Message kind from a business agent proposing one slot: service, start, duration, price, currency, and from Phase 2 a stored `offerId`, `issuedAt` and `expiresAt`.                                                                                                                                                                                                                                           |
| Offer declined (`offer_declined`)    | Message kind a personal agent sends when the person declines; it releases the hold at once (FR-BOOK-08).                                                                                                                                                                                                                                                                                                     |
| Offer match                          | The check that an offer answers the request it replies to: same service and a start inside the requested window (`offerMatches`, FR-MSG-04).                                                                                                                                                                                                                                                                 |
| Person-to-person agreement (UC-11)   | Two people's agents agree a time between them (for example a coffee or a call), each person approving before anything is committed. Phase 4, in the client app.                                                                                                                                                                                                                                              |
| Personal agent                       | The agent acting for a person. The built-in agent in the client app is the consumer agent at Phase 4 launch.                                                                                                                                                                                                                                                                                                 |
| PRD (product requirements document)  | The document stating what the product does for whom: problem, personas, features with MoSCoW and FURPS+, the user story backlog (US-) with acceptance criteria, release plan and success metrics (HP-SAD-24).                                                                                                                                                                                                |
| Phase                                | One stage of the delivery plan, 0 to 6 then Later, each with an exit gate (HP-SAD-16).                                                                                                                                                                                                                                                                                                                       |
| Phase gate                           | The review at the end of a phase that checks its exit criteria before the next phase starts.                                                                                                                                                                                                                                                                                                                 |
| Prompt injection                     | Text crafted to make a language model follow instructions it shouldn't. Inbound agent data is treated as data, never instructions.                                                                                                                                                                                                                                                                           |
| Protocol-safe work                   | Work done during the A-01 test that is worth keeping even if A-01 fails and the project stops at Phase 1: book validation, the e2e contract tests, the extension header, the conformance kit, operational basics, security CI and the ADR notes (HP-SAD-16).                                                                                                                                                 |
| Quality attribute scenario           | A testable statement of a quality requirement: source, stimulus, environment, artifact, response, response measure (HP-SAD-11).                                                                                                                                                                                                                                                                              |
| RAID log                             | The consolidated register of risks, assumptions, issues (I-) and dependencies (DP-), with owners and status (HP-SAD-33).                                                                                                                                                                                                                                                                                     |
| Rejected                             | Message kind a business agent returns when it can't validate a request.                                                                                                                                                                                                                                                                                                                                      |
| Reserved hold                        | **Later**, with manual approval. The hold on an offer after its `booking_request` is accepted while the business decides; it lasts until the business answers or P-03 passes (P-02).                                                                                                                                                                                                                         |
| SOW (statement of work)              | The document that contracts the work: scope, deliverables, milestones, acceptance criteria, assumptions, responsibilities and change control (HP-SAD-25).                                                                                                                                                                                                                                                    |
| Slot                                 | A start time on the 30-minute grid in which a service fits inside opening hours and overlaps no booking or hold.                                                                                                                                                                                                                                                                                             |
| SLI and SLO                          | Service level indicator (what is measured) and objective (the target), for example offer round trip p95 under 2 s.                                                                                                                                                                                                                                                                                           |
| Standing approval                    | Business-side rule that a business's published hours and services count as its approval to book any free slot. The only approval mode in the pilot.                                                                                                                                                                                                                                                          |
| STRIDE                               | Threat classification: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege.                                                                                                                                                                                                                                                                                  |
| Task (A2A)                           | Stateful A2A unit of work with a lifecycle (submitted, working, input-required, completed, rejected, failed, canceled). Hitchpost uses Tasks for commitments: book and cancel ([ADR 0012](../decisions/0012-booking-protocol.md)); a reschedule question is a Message. In the pilot a booking Task completes at once under standing approval; Hitchpost never uses input-required for waiting on a business. |
| Time zone rule                       | Phase 6 (ADR 0018): UTC on the wire; each business has an IANA time zone; hours are minutes of the local day; the slot grid starts at local opening time; a skipped local time gives no slot and a repeated one is offered once. Before Phase 6 everything is UTC and demo-only.                                                                                                                             |
| Trust boundary                       | A line across which data changes trust level, labelled B1 to B6 in HP-SAD-12.                                                                                                                                                                                                                                                                                                                                |
| Unresolved                           | Booking outcome when neither side marks it within P-25 (7 days). Excluded from the north star; the unmarked rate is a counter-metric.                                                                                                                                                                                                                                                                        |
| Untrusted data                       | Anything received from another agent or the network. Validated and rebuilt before use (FR-MSG-03).                                                                                                                                                                                                                                                                                                           |
| Verified business                    | A listing whose control of its domain has been proven by a well-known token or DNS TXT record (FR-DIR-01).                                                                                                                                                                                                                                                                                                   |
| Verified interaction                 | An interaction with a logged offer and a matching logged decision on both sides, ending in a booking that reached Completed or NoShow. Only these can be rated (FR-RATE-01). Same wording as [05](05-requirements.md).                                                                                                                                                                                       |
| Walking skeleton                     | The smallest end-to-end slice that runs through the whole pipeline ([ADR 0009](../decisions/0009-walking-skeleton.md)).                                                                                                                                                                                                                                                                                      |
| Wizard of Oz test                    | A test where a person plays the system by hand to learn whether users want it before it is built (A-01).                                                                                                                                                                                                                                                                                                     |

## 4. ID prefix legend

Every ID family in the package, with where it's defined. Prefixes are chosen so no two families can be confused: in particular P-01 to P-29 are parameters, P1 to P7 (no dash) are DFD processes, UI principles use UP-, and business requirements use BR-REQ- so they never collide with business rules (BR-).
